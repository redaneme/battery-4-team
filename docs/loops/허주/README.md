# 허주의 Loop 설계

battery 프로그램에 **새 기능을 추가할 때** 쓰는 Loop(기능 추가용)입니다.
Dynamic Workflow로 만들며, 이 문서에는 **설계 설명만** 적습니다. (Loop 코드는 이 PR에 없습니다.)

## 1. 한 줄 설명

"이런 기능을 추가해 주세요"라는 요청을 받으면 **먼저 점검**하고, 사람이 계획을 **승인**하면 **구현**한 뒤, **검증**해서 결과를 HTML 두 장으로 남깁니다.

## 2. 범위

- **다루는 일:** 화면·API·DB에 새 기능이나 새 항목을 더하는 일 (예: 주문에 고객사 입력 추가)
- **다루지 않는 일:** 버그 수정, 리팩토링. 점검과 검증 방법이 달라서 이번에는 기능 추가 하나만 만듭니다.

## 3. 흐름

```
 요청
  ▼
[사전 검토]  Node 3개가 따로 점검 ──► precheck.html
  ▼
[세팅]       증거 폴더 준비, 계획(Plan) 작성
  ▼
 ★ HITL ①   사람이 점검 결과와 계획을 보고 승인 / 수정 / 중단
  ▼
[구현]       승인된 계획대로 코드 수정
  ▼
[검증]       Node 3개가 빌드·테스트·리포트 ──► report.html
  ▼
 ★ HITL ②   사람이 결과를 보고 승인 / 수정 요청
  ├─ 수정 요청 ─► [Feedback] ─► 구현으로 돌아감 (최대 3번)
  ▼
 완료  (commit·PR은 사람이 직접)
```

각 Node는 Subagent라서 **새 대화로 시작**합니다. 앞 단계 생각에 끌려가지 않아 오작동이 줄어듭니다.

## 4. 단계별로 하는 일

**구현 전 (사전 검토 Node 3개 + 계획)**

| Node | 하는 일 |
|---|---|
| A. 문서 규칙 | 요청이 `PRD.md`, `INTENT.md`와 어긋나는지 본다. |
| B. 영향 범위 | 바뀌는 파일과 영향받는 화면·API·DB·기존 테스트를 찾는다. |
| C. 빠진 정보·위험 | 정해지지 않은 것(기본값, 기존 데이터 처리)을 질문으로 정리한다. |
| 계획 | 무엇을 어떤 순서로 바꿀지 쓴다. |

**구현 후 (검증 Node 3개)**

| Node | 하는 일 |
|---|---|
| D. 빌드·단위 테스트 | 빌드와 기존 단위 테스트를 실행한다. |
| E. E2E 회귀 테스트 | 기존 E2E(E2E-021~030 등)를 별도 포트·메모리 DB로 실행해 원래 되던 흐름이 깨지지 않았는지 본다. |
| F. 요약·리포트 | 바뀐 파일이 계획과 같은지 대조하고, 구현 요약과 검증 결과를 정리한다. |

**HITL(사람이 확인하는 곳)**
- ① 구현 전: 점검 결과와 계획 승인. 승인 전에는 코드를 바꾸지 않습니다.
- ② 구현 후: 결과 승인 또는 수정 요청.

## 5. 끝나는 조건

- **정상 종료:** 빌드·테스트가 통과하고 사람이 ②에서 승인
- **중단:** 사람이 ①에서 중단을 선택
- **사람에게 넘김:** 3번 반복해도 검증이 통과하지 않음 (원인을 report에 적고 멈춤)

## 6. 산출물

```
docs/evidence/허주/{작업번호+작업명}/     예: TASK-001-customer-name
├─ precheck.html   구현 전 점검 내용 (요청 요약, 문서 규칙, 영향 범위, 위험, 계획)
└─ report.html     구현 요약, 바뀐 파일, 빌드·테스트 결과, 반복 횟수, 남은 문제
```

두 HTML의 공통 템플릿은 팀에서 협의해 정하는 것을 따릅니다.

## 7. 지키는 규칙

- 코드 수정은 ①에서 승인된 뒤에만 합니다.
- 개발 앱(8080)과 개발 DB는 건드리지 않습니다.
- commit, push, PR, 배포는 자동으로 하지 않습니다. 사람이 요청할 때만 합니다.
- 확인하지 못한 것은 "확인하지 못함"이라고 적고, 통과했다고 쓰지 않습니다.
- 가정한 내용(실습용 시스템이라 데이터가 불완전할 수 있음)은 HTML에 적어 둡니다.

## 8. 이번에 넣지 않은 것

Lint·Formatter, 보안·아키텍처 검증, 자동 commit·PR·배포, 버그 수정용·리팩토링용 Loop. 필요하면 Node를 추가해 확장합니다.

## 9. 테스트 계획

확인용 요청으로 Loop를 한 번 돌려 봅니다.

> 주문할 때 **고객사**를 입력하고, 주문 목록에서도 고객사 이름을 볼 수 있게 한다.

- 확인할 것: `precheck.html`과 `report.html`이 위 폴더에 제대로 만들어지는지
- 이 테스트로 바뀐 코드는 **commit하지 않습니다.**
