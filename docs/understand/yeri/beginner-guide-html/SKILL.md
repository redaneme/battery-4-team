# 비개발자용 단계별 이해 가이드 (HTML) 만들기

코드를 처음 보는 사람이 **개발 지식 없이**, **탭으로 단계별**, **직접 눌러 보며** 프로젝트를 이해하게 하는 단일 HTML 파일을 만든다.
목적은 이해 자체보다, 이후 **코드 리뷰를 편하게 하는 것**이다.

완성된 예시: `references/example_basic_guide.html` (배터리 주문 프로젝트). 구조·스타일·탭 스크립트를 참고하되 **내용은 대상 프로젝트에 맞게 새로 쓴다.**

## 0. 먼저 확인할 것 (모르면 짧게 물어본다)

- 출력 경로: 기본값 `./docs/understand/yeri/basic_guide.html` (이미 있으면 `_v2` 등 새 이름으로 저장하고 덮어쓰지 않는다)
- 탭 개수: 기본값 3개
- 독자가 정해져 있는지 (없으면 "중학생도 이해할 수 있는 수준")

이미 알려 준 값은 다시 묻지 않는다.

## 1. 프로젝트를 먼저 이해한다

1. 소스를 읽고 **업무(요구사항) 관점**에서 정리한다: 누가, 무엇을 입력하고, 무엇을 얻는가.
2. 도메인 규칙(제한, 계산 방식, 상태 변화, 안전장치)과 **기본값 숫자**를 코드에서 찾는다.
3. 화면 흐름과 사용자가 하는 행동 순서를 정리한다.
4. 이해가 안 되는 부분은 지어내지 않는다. 확인하지 못한 내용은 가이드에 넣지 않거나 "추정"이라고 밝힌다.

## 2. 탭 구성 원칙 (바깥에서 안쪽으로)

| 탭 | 질문 | 내용 |
|---|---|---|
| 1단계 | 이게 뭐 하는 프로그램이에요? | 한 줄 요약 + 비유 + 등장인물(데이터·역할) 둘러보기 |
| 2단계 | 핵심 동작이 뭐예요? | 가장 중요한 규칙 1~2개를 체험으로 보여 준다 |
| 3단계 | 어떤 안전·관리 규칙이 있어요? | 상태 변화, 충돌, 변경 시 보호 규칙 등 |

- 각 탭은 **그 탭만 읽어도 완결**되게 한다. 앞 탭을 몰라도 되는 부분은 반복해서 설명한다.
- 탭 끝에 "정리" 박스 또는 짧은 퀴즈를 둬서 이해를 확인하게 한다.
- 프로젝트 성격상 3단계가 맞지 않으면(예: 화면이 거의 없는 라이브러리) 개수와 주제를 조정하되, 단계가 깊어질수록 어려워지는 순서는 지킨다.

## 3. 글쓰기 규칙

- **개발 용어 금지**: API, 엔티티, 트랜잭션, 낙관적 락, DB, 서버 등은 쓰지 않는다. 필요하면 일상어로 바꾼다.
  (예: "낙관적 락 충돌" → "두 사람이 동시에 바꾸면 나중에 누른 사람은 거부돼요")
- 내부 단위·약어(K, ms, 행 등)는 사람이 읽는 단위로 바꿔 보여 준다.
- 비유를 1개 이상 쓴다 (택배, 창고, 식당 주문 등 일상 상황).
- 문장은 짧게, 존댓말(~해요/~입니다)로 쓴다. 화면 문구는 대상 프로젝트의 언어를 따른다.
- 숫자는 **코드의 실제 기본값**을 그대로 쓴다. 임의로 만든 숫자를 쓰지 않는다.

## 4. 인터랙션 규칙

탭마다 **직접 눌러 볼 수 있는 것**을 최소 1개 넣는다.

- 좋은 인터랙션: 슬라이더로 값을 바꾸면 결과가 즉시 바뀐다 / 버튼으로 하루씩 진행한다 / 상태 버튼을 눌러 "갈 수 있는 길만 열려 있음"을 체험한다 / 두 사용자 시나리오로 충돌을 재현한다.
- 인터랙션은 **실제 코드의 규칙을 그대로 따른다.** 규칙을 단순화했으면 화면에 "이 체험은 ~만 다룬다"고 명시한다.
- 잘못된 조작에는 막히는 이유를 그 자리에서 보여 준다 (빨간 안내 박스).
- 모든 체험에 "처음부터" 버튼을 둔다.
- 알고리즘이 복잡한 부분(최적화 등)은 재현하지 않는다. 핵심 직관만 보여 주고 "프로그램이 대신 계산해 준다"고 안내한다.

## 5. 기술 규칙

- **단일 HTML 파일**, 외부 라이브러리·CDN·이미지 없이 CSS/JS 인라인. 파일을 더블클릭하면 바로 열려야 한다.
- 색상은 CSS 변수로 정의하고 `prefers-color-scheme: dark`를 지원한다.
- 모바일 폭에서도 깨지지 않게 한다 (`viewport`, flex/grid wrap).
- 탭은 `role="tablist"/"tab"/"tabpanel"`, 방향키 이동을 지원한다. 마지막 탭은 `localStorage`에 저장하되 `try/catch`로 감싼다.
- 지도·도식은 인라인 SVG, 클릭 가능한 요소는 `tabindex`와 Enter/Space 키를 지원한다.
- 구조는 `references/example_basic_guide.html`을 출발점으로 삼아도 된다 (탭 스크립트, 카드/노트/통계 스타일, 퀴즈, 로그 박스 등).

## 6. 검증

1. 인라인 스크립트를 추출해 `node --check`로 문법을 검사한다.
2. 가능하면 브라우저(Playwright 등)로 열어 탭 전환과 각 체험을 한 번씩 눌러 본다. 하지 못했으면 사용자에게 **직접 눌러 보지 못했다**고 말한다.
3. 가이드 안의 숫자·규칙을 코드와 대조한다.

## 7. 마무리 보고

- 파일 경로, 탭별 주제와 체험 목록을 표로 간단히 알린다.
- 단순화했거나 재현하지 않은 부분을 명시한다.
- **커밋·푸시는 하지 않는다.** 사용자가 요청할 때만 한다.
