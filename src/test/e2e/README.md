# battery E2E 테스트 — E2E-021 ~ E2E-030 (허주)

`../../e2e/e2e-test-scenarios-final.xlsx`의 시나리오 E2E-021 ~ E2E-030을 Playwright로 만든 테스트입니다.
이 폴더 안에서 독립적으로 동작하며, 다른 팀원의 테스트와 설정을 공유하지 않습니다.

## 실행

```
cd src/test/e2e
npm install        # 처음 한 번
npx playwright test        # headless (기본)
npm run test:headed        # 브라우저 창을 보면서 실행
```

- 테스트가 앱을 직접 띄웁니다. **포트 8091, 메모리 DB**라서 개발 앱(8080)과 개발 DB를 건드리지 않습니다.
- 처음에는 Gradle이 앱을 빌드하느라 시간이 걸립니다(최대 4분 대기). 이후에는 20초 안팎입니다.
- 브라우저는 PC에 설치된 **Chrome**을 씁니다. 별도 다운로드가 없습니다.
- 시나리오가 주문을 만들고 마스터를 바꾸므로 한 번에 하나씩, 파일 이름 순서로 실행합니다. 마스터를 바꾸는 E2E-022는 끝에서 반드시 원복합니다.

## 결과 리포트

```
npm run test:report
```

headless 로 전체를 실행하고 `docs/playwright/허주/report/` 에 결과를 만듭니다. PR에는 이 폴더를 함께 올립니다.

- `docs/playwright/허주/report/report.md` : 시나리오별 통과·실패와 소요 시간, 실행 환경, 테스트 코드 커밋
- `docs/playwright/허주/report/html/index.html` : Playwright HTML 리포트 (실패 시 스크린샷·트레이스 포함)
- `docs/playwright/허주/report/results.json` : Playwright JSON 결과

## 시나리오와 테스트

| 시나리오 | 파일 | 확인하는 것 |
|---|---|---|
| E2E-021 | `e2e-021.spec.ts` | 확정 요청에 끼워 넣은 `totalCost=1, totalDays=1`은 무시되고 서버가 다시 계산한 값으로 저장 |
| E2E-022 | `e2e-022.spec.ts` | 마스터를 바꿔도 확정한 주문은 그대로, 새 주문만 새 기준을 따름 (마스터 원복 포함) |
| E2E-023 | `e2e-023.spec.ts` | 목록의 열 8개, 방금 확정한 주문이 맨 위, 번호 내림차순 |
| E2E-024 | `e2e-024.spec.ts` | 칩 건수 = 행 수, 전체 = 확정+진행+완료+취소, 칩을 누르면 그 상태만 보임 |
| E2E-025 | `e2e-025.spec.ts` | 상세에 확정 정보, 이력, 요약, 표, 애니메이션이 모두 있고 자동 재생되지 않음 |
| E2E-026 | `e2e-026.spec.ts` | 일별 재고는 지도 애니메이션 슬라이더로 본다(표에는 재고 열 없음). 슬라이더 값 = 서버 계산 재고, 수거한 날 그 나라 재고 0 |
| E2E-027 | `e2e-027.spec.ts` | 확정 → 진행: 확인 창 문구, 배지, 안내 메시지, 이력 행 |
| E2E-028 | `e2e-028.spec.ts` | 확인 창에서 [취소]를 누르면 상태·이력이 그대로 |
| E2E-029 | `e2e-029.spec.ts` | 진행 → 완료 후 변경 버튼이 사라지고 이력이 3행 |
| E2E-030 | `e2e-030.spec.ts` | 확정은 [진행·취소], 진행은 [완료·취소] 버튼만 있음 |

## 참고

- `huju-helpers.ts`: 로그인, 시뮬레이션·주문 생성·상태 변경(사전 조건 만들기용 API 호출), 이력·목록 읽기.
- 사전 조건은 API로 빠르게 만들고, 시나리오가 확인하려는 동작은 화면으로 직접 확인합니다.
- E2E-024의 '취소' 건수는 개발 DB에 옛 취소 주문이 있을 수 있어서 값을 정하지 않고 행 수와 같은지만 봅니다.
